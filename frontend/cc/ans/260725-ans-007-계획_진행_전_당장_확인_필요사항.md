## 1. 지금 바로 백엔드에 보내야 하는 질의 — 작업 3 전체가 블로킹됨

작업 1·2·4는 확인 없이 즉시 착수 가능하지만, 아래 2건은 답이 오기 전까지 **작업 3(플랜 장소)을 시작조차 할 수 없으므로** 오늘 질의 발송이 필요.

1. **`departurePoint` 처리 방식** — plan-place preview/update에서 생략 시 저장된 출발지가 유지되는가, null로 덮어써지는가? `PlanDetailDto`에 departurePoint를 추가해줄 수 있는가?
   - 현재 클라이언트에는 기존 플랜의 출발지를 얻을 데이터 소스가 전무해, 백엔드 답변에 따라 수정 방식 (a)/(b)가 갈림.
2. **스탬프 `location` 필수 여부** — 파트 생략 시 400인가, 위치 검증 없이 승인인가?
   - 필수면 위치 권한 거부 사용자 차단 UI가 필요하고, 선택이면 현행 유지.

## 2. 착수는 가능하나 완료(머지) 전에 답이 필요한 것

구현은 명세 기준으로 진행하되, 아래는 검증 단계 전에 확정 필요.

- **댓글 응답이 정말 wrapper 없이 raw DTO/number인지 실응답 샘플 1건** — 작업 1 전체의 전제. 과거 백엔드가 `{status, data}` wrapper를 썼던 흔적이 있어 스펙만 믿기엔 위험.
- **플랜 생성**: 프리뷰 실패 시 0 기본값 전송 허용 여부 + `totalDistance` 단위(m 확정?) — 단위에 따라 `CourseCreationFlow.tsx:1315` km 표기가 1000배 오표기.
- **제재 등록 실응답**: 응답 키가 명세 그대로 `adminReportDetailResponseDto`인지, `sanctionId` 타입(number/string), status code(200 vs 201).

## 3. 팀 내부(연주/기획)에서 결정할 사항 — 백엔드 무관

- **MySanctions 화면**: "내 제재 목록" API가 v6에 없음 — 백엔드에 신설 요청할지, 화면을 명시적 비활성 처리할지.
- **admin mock 폴백**: 완전 제거 vs env 기반 dev 게이트 유지 — 백엔드 미기동 환경에서 관리자 화면 개발 편의를 남길지 결정.
- **플랜 복제 `scheduledDate`**: `CourseViewPage`의 바디 없는 복제 호출 수정 시 날짜 선택 모달을 띄울지, 기본값(오늘/tripStartDate)을 쓸지.

## 4. 로컬 환경 확인 — 검증 자체가 안 될 수 있음

- **`NEXT_PUBLIC_API_BASE_URL` 설정 여부**: 저장소에 `.env` 파일이 없음. 미설정 시 apiClient 직행 호출(댓글·신고·플랜 등)이 Next 서버로 가서 전부 404 — 작업 1의 수동 검증이 불가능. 백엔드(`localhost:3845`) 기동과 함께 착수 전 확인.
