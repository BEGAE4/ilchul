## 1. 사용자 좌표 정보를 DB에 저장할 필요가 있는가?

### 1-1. 현재 코드에서 사용자 좌표(위치정보)를 사용하는 지점

| # | 기능 | 파일 | 좌표의 흐름 | 서버 전송 여부 |
|---|------|------|------------|---------------|
| 1 | 홈 — 내 주변 인기 플랜/장소 | `src/app/page.tsx`, `src/features/main/hooks/useGeolocation.ts`, `src/features/main/components/PopularPlanListPage`, `PopularPlaceListPage` | `navigator.geolocation` → `GET /api/plan/popular?lat&lng`, `GET /api/place/popular?lat&lng` | 전송 O (쿼리 파라미터, 일회성 조회) |
| 2 | 코스 작성 — 출발지 "현재 위치로 설정" | `src/features/course-creation/components/CourseCreationFlow.tsx` | 현재 위치 좌표 → 플랜 생성 시 `departurePoint { name, address, x, y }`로 전송 | 전송 O (플랜의 출발지 속성으로 저장됨) |
| 3 | 내 코스 — 방문 인증 스탬프 | `src/features/my-course/components/MyCourseDetailPage.tsx` | 현재 위치 → `POST /api/plan-place/{planPlaceId}/stamp` body의 `location { x, y }` | 전송 O (장소 방문 검증 용도) |
| 4 | 장소 상세 — 길찾기/지도 열기 | `src/features/place-detail/components/PlaceDetailPage.tsx` | `map.kakao.com/link/...` 웹 링크로 새 창 열기 | 전송 X (클라이언트에서만 사용) |

### 1-2. 결론: **사용자 좌표를 별도로 DB에 저장할 필요는 없다**

| 사용처 | 저장 필요 여부 | 근거 |
|--------|--------------|------|
| ① 내 주변 인기 조회 | **불필요** | 요청 시점의 좌표로 주변을 조회하는 일회성 파라미터. 다음 요청 때 다시 받으면 되고, 이력을 저장해도 기능상 쓰임이 없음 |
| ② 플랜 출발지 | **저장 필요 (이미 명세에 반영됨)** | `departurePoint`는 "사용자의 위치 이력"이 아니라 **플랜의 구성 데이터**. 플랜 재조회·경로 안내에 필요하므로 플랜 테이블에 저장하는 것이 맞고, v6 명세(`cc/api/v6/260723-v6-005-plan-place.md`)에 이미 포함되어 있음 |
| ③ 스탬프 인증 좌표 | **검증 후 폐기 권장** | 서버는 장소 좌표와 대조해 `isStamped` 판정만 하면 됨. 저장이 필요한 것은 판정 결과(`isStamped`, `stampedAt`, `verifiedImage`)이지 사용자 원본 좌표가 아님 |
| ④ 길찾기 링크 | 무관 | 서버로 전송조차 되지 않음 |

즉, **"사용자 좌표" 자체를 저장하는 테이블/컬럼을 새로 만들 필요는 없고**, 현재 v6 명세대로 ▲플랜 출발지 좌표(플랜 데이터)만 저장하면 충분하다. 스탬프 인증의 `location`은 검증에만 쓰고 영속화하지 않는 것을 백엔드에 권장한다.

### 1-3. 저장하지 않는 것이 유리한 이유 (법적 리스크)

사용자의 실시간 좌표는 「위치정보의 보호 및 이용 등에 관한 법률(위치정보법)」상 **개인위치정보**에 해당한다.

- 개인위치정보를 이용해 서비스를 제공하는 사업자는 원칙적으로 **위치기반서비스사업 신고** 대상 (전자민원센터 [emsit.go.kr](https://www.emsit.go.kr/cp/cv/Cp1440000_0182_01Reg.do)에서 온라인 신고)
- 단, **소상공인·1인창조기업은 사업 개시 후 1개월까지 신고 없이 개시 가능**하고, 계속 운영하려면 그 이후 (간이)신고를 하면 된다 — [위치정보지원센터: 소상공인 등의 위치기반서비스 사업신고](https://www.lbsc.kr/front/content/contentViewer.do?contentId=CONTENT_0000091)
- 참고로 **주소(거주지·배송지)는 위치정보가 아니라 개인정보**로 분류되어 이 신고 대상이 아니다
- 좌표를 **저장·축적하지 않고 요청 처리 시에만 이용 후 폐기**하는 구조로 가면, 수집·보관 항목이 줄어 개인정보 처리방침·유출 리스크·신고 심사 부담이 모두 가벼워진다

> 이 신고는 카카오가 아니라 정부(방송통신위원회 관할) 절차이므로, 카카오 API 사용 여부와는 별개다. 공모전/팀 프로젝트 단계에서는 소상공인 특례 범위에서 진행 가능하나, 정식 서비스 런칭 시 신고 여부를 재검토할 것.

### 2-2. 기능별 사업자(비즈 앱) 필요 여부 정리

| 카카오 기능 | 사업자 필요? | 상세 |
|------------|-------------|------|
| 카카오 로그인 — 닉네임·프로필 사진 동의 | **불필요** | 일반 앱으로 사용 가능 |
| 카카오 로그인 — **카카오계정 이메일 "필수 동의"** | **비즈 앱 필요** (사업자 없이도 가능) | **개인 개발자 비즈 앱**으로 전환하면 사업자등록번호 없이 가능. 앱 소유자 카카오계정 본인인증 + 카카오비즈니스 통합 서비스 약관 동의 필요 |
| 카카오 로그인 — 성별·연령대·전화번호 등 추가 동의항목 | **사업자 인증 비즈 앱 + 검수 필요** | 사업자등록번호 등록 후 "추가 기능 신청"으로 항목별 검수(영업일 3~5일) |
| 카카오톡 공유 (기본) | **불필요** | JavaScript 키 + 플랫폼(도메인) 등록만으로 사용 가능. 권한 신청 없음 |
| 카카오톡 공유 — 공유 대상 선택 화면 커스텀 | 비즈 앱 필요 | 사업자 정보 입력 후 비즈 앱 전환 |
| 카카오톡 메시지 API (친구에게 발송) | 권한 신청 필요 | 별도 사용 권한 신청 대상 — 현재 기획에는 없음 |
| 카카오맵 웹 링크 (`map.kakao.com/link/...`) | **불필요** | API 키조차 필요 없음 (현재 구현 방식) |
| 카카오맵 JS SDK / 로컬 API (향후 도입 시) | 조건부 | 2026-07-21부터 **개발자 계정 기준 첫 번째 활성화 앱은 무료 쿼터 제공**(신규 길찾기·정적 지도 일 1,000건 등, 기존 지도/로컬 API는 기존 제공량 유지). **두 번째 앱부터는 비즈월렛 연결 + 유료 API 설정 필요** |
| 카카오싱크 / 비즈니스 채널 연결 | **사업자 인증 필수** | 개인 개발자 비즈 앱으로는 비즈니스 채널 연결 불가 |

### 2-3. 일출 프로젝트 기준 판단

1. **당장 사업자등록이 필수인 기능은 없다.**
   - 로그인(닉네임·프로필), 카카오톡 기본 공유, 지도 웹 링크 — 전부 일반 앱/개인 개발자 범위에서 가능.
2. **이메일을 회원 식별자로 쓰려면 "개인 개발자 비즈 앱" 전환이 필요하다.** 사업자등록번호 없이 본인인증만으로 가능하므로, 백엔드가 카카오 로그인 시 이메일을 필수로 받고 있다면 이 전환을 진행해야 한다. (백엔드 담당자와 앱 소유 계정 확인 필요)
3. **전화번호·성별·연령대 수집, 카카오싱크, 비즈니스 채널 연동을 기획에 넣는 순간 사업자등록번호가 필요해진다.** 현재 UI/기획 범위에는 해당 기능이 없으므로 당장은 불필요.
4. 카카오맵 SDK를 향후 도입해도 **팀의 첫 번째 앱이라면 무료 쿼터로 시작 가능**하다.

## 3. 신청 방법

### 3-1. 개인 개발자 비즈 앱 전환 (사업자등록번호 불필요 — 이메일 필수 동의 목적)

1. [Kakao Developers](https://developers.kakao.com) 로그인 → **내 애플리케이션** → 해당 앱 선택
2. 앱 소유자(Owner) 카카오계정의 **본인인증**을 완료 (카카오계정 설정에서 휴대폰 본인인증)
3. **앱 설정 > 비즈니스** 메뉴에서 **개인 개발자 비즈 앱 전환** 신청
   - 카카오비즈니스 통합 서비스 약관 동의
   - 앱 이름·아이콘·회사명(팀명)을 실제 서비스와 일치하게 설정해 둘 것 (반려 사유가 됨)
4. 전환 완료 후 **제품 설정 > 카카오 로그인 > 동의항목**에서 `카카오계정(이메일)`을 **필수 동의**로 변경
5. 메뉴에서 전환이 막혀 있거나 반려되면 [카카오 데브톡](https://devtalk.kakao.com)에 "개인 개발자 비즈 앱 전환 신청 (앱 ID: xxx)" 게시글로 요청하는 사례가 일반적

### 3-2. 사업자 인증 비즈 앱 전환 (전화번호 등 추가 동의항목·카카오싱크 필요 시)

1. **내 애플리케이션 > 앱 설정 > 비즈니스**에서 **사업자등록번호 등록**
2. 등록 승인 후 비즈 앱으로 전환됨
3. **추가 기능 신청**에서 필요한 동의항목(전화번호, 성별, 연령대 등)별로 검수 신청
   - 수집 목적·이용 시나리오를 구체적으로 작성해야 하며, 검수에 **영업일 3~5일** 소요
4. 비즈니스 채널 연결·카카오싱크는 사업자 인증 비즈 앱에서만 가능

### 3-3. 카카오톡 공유 구현 시 (ShareBottomSheet 연동 예정 기능)

사업자 신청 없이 아래만 하면 된다:

1. 내 애플리케이션 > **앱 설정 > 플랫폼 > Web**에 서비스 도메인 등록
2. **JavaScript 키** 발급 확인 → 프론트에서 Kakao JS SDK 초기화 (`Kakao.init(JS_KEY)`)
3. `Kakao.Share.sendDefault(...)`로 공유 구현 — 별도 권한 신청 없음

### 3-4. (참고) 위치기반서비스사업 신고 — 카카오 아님, 정부 절차

- 대상: 개인위치정보를 수집·이용해 서비스를 제공하는 사업자
- 신고처: [전자민원센터(emsit.go.kr)](https://www.emsit.go.kr/cp/cv/Cp1440000_0182_01Reg.do) 온라인 접수
- 특례: 소상공인(상시근로자 10인 미만 등)·1인창조기업은 **사업 개시 후 1개월까지 신고 면제**, 이후 계속 운영 시 신고
- 상세 안내: [위치정보지원센터(lbsc.kr)](https://www.lbsc.kr/)

## 4. 요약

- **사용자 좌표 DB 저장: 불필요.** 저장할 것은 플랜의 출발지 좌표(이미 v6 명세에 포함)뿐이고, 홈 주변 조회·스탬프 인증 좌표는 일회성 이용 후 폐기하는 것이 기능·법적 리스크 양면에서 유리하다.
- **카카오 사업자 신청: 당장 필수인 기능 없음.** 단, 카카오 로그인에서 **이메일을 필수 동의로 받으려면 "개인 개발자 비즈 앱" 전환**(사업자 불필요, 본인인증만)이 필요하고, **전화번호·성별·연령대·카카오싱크**를 쓰게 되면 그때 사업자등록번호가 필요하다.
- 카카오톡 공유(미구현)와 현재의 지도 웹 링크 방식은 사업자·권한 신청 없이 구현 가능하다.
