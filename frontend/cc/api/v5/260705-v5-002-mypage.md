# MYPAGE API (v5)

> 원본: [api-docs.json](api-docs.json) — `my-page-controller`

| 제목 | 메서드 | URL | 응답 스키마 |
| --- | --- | --- | --- |
| 프로필 조회 | GET | `/api/mypage/profile` | `UserProfileResponseDto` |
| 프로필 수정 | PATCH | `/api/mypage/profile` | `UserProfileResponseDto` |
| 프로필 요약(카운트) 조회 | GET | `/api/mypage/summary` | `UserProfileSummaryResponseDto` |
| 내 플랜 목록 조회 | GET | `/api/mypage/plans` | `MyPlansResponse` |
| 내 스크랩 플랜 목록 조회 | GET | `/api/mypage/scrapped` | `ScrappedPlanResponseDto` |
| 내 플랜 공개 여부 토글 | POST | `/api/mypage/plan/visibility/{planId}` | 200 (본문 없음) |

---

## 1. 프로필 조회 / 수정

### PATCH 요청 본문 (`UpdateUserProfileRequest`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| newUserNickname | String | 새 닉네임 |
| newUserIntro | String | 새 소개글 |
| newUserProfileImg | String | 새 프로필 이미지 URL |

### 응답 (`UserProfileResponseDto`)

```json
{
  "userNickname": "힙스터김",
  "userImg": "https://example.com/profile.jpg",
  "userIntro": "여행을 좋아합니다"
}
```

## 2. 프로필 요약 조회

## 4. 내 스크랩 플랜 목록 조회

### 응답 (`ScrappedPlanResponseDto` → `ScrappedPlanSummary[]`)

`PlanSummary`와 동일 필드 구조이며 키 이름만 `scrappedPlans`.

```json
{
  "scrappedPlans": [
    {
      "planId": 13,
      "planTitle": "바다 보러 가는 날",
      "createAt": "2026-05-20T10:00:00",
      "tripStartDate": "2026-06-01T09:00:00",
      "tripEndDate": "2026-06-01T20:00:00",
      "isPlanVisible": true,
      "requiredTime": 660,
      "planImages": []
    }
  ]
}
```

---

## 5. 내 플랜 공개 여부 토글

- `POST /api/mypage/plan/visibility/{planId}`
- **요청 본문 없음** — 호출할 때마다 공개 ↔ 비공개 토글로 추정 (v4의 `PATCH /api/plan/{planId}/visibility` + `{ isPublic }` 방식에서 변경됨)
- 응답: 200 (본문 없음)
