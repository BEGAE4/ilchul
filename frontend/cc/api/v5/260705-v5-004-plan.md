## 1. 플랜 생성 — POST `/api/plan/create`

v4와 달리 **출발지, 여행 일정, 장소 목록까지 한 번에 등록**한다.

### 요청 본문 (`CreatePlanRequestDto`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| planTitle | String | 플랜 제목 |
| isPlanVisible | Boolean | 공개 여부 |
| planDescription | String | 플랜 설명 |
| requiredTime | Integer | 총 소요 시간(분) |
| totalDistance | Integer | 총 이동 거리 |
| departurePoint | `DeparturePointDto` | 출발지 `{ name, address, x, y }` |
| tripStartDate / tripEndDate | date-time | 여행 시작/종료 일시 |
| places | `CreatePlanPlaceRequest[]` | 장소 목록 `{ placeId, order, travelTime, stayTime }` |

### 응답 (`CreatePlanResponseDto`)

```json
{
  "planId": 27,
  "planTitle": "성수동 힙플레이스 완전 정복",
  "createAt": "2026-07-05T10:00:00",
  "planVisible": false
}
```

## 3. 플랜 수정 — PATCH `/api/plan/{planId}`

### 요청 본문 (`UpdatePlanRequestDto`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| planTitle | String | 제목 |
| isPlanVisible | Boolean | 공개 여부 |
| planDescription | String | 설명 |
| tripStartDate / tripEndDate | date-time | 여행 일정 |

### 응답 (`UpdatePlanResponseDto`)

```json
{ "planId": 27 }
```

---

## 4. 플랜 이미지 업로드 / 삭제

- 업로드: `POST /api/plan/{planId}/images` — `images` (binary 배열, query로 정의되어 있으나 실제로는 multipart 전송으로 추정)
- 삭제: `DELETE /api/plan/{planId}/images?imageIds=1,2`
- 응답: 둘 다 갱신된 `PlanDetailDto`

---

## 5. 플랜 복제 (일정 담기) — POST `/api/plan/{planId}/clone`

### 요청 본문 (`PlanCopyRequestDto`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| scheduledDate | date | 복제한 플랜의 예정일 |

### 응답 (`PlanCopyResponseDto`)

```json
{ "planId": 31, "originalPlanId": 27, "createAt": "2026-07-05T10:00:00" }
```

## 6. 플랜 좋아요 — POST / DELETE `/api/like/{planId}`


## 7. 플랜 스크랩 — POST `/api/plan/scrapped/{planId}`

- **POST 단일 엔드포인트(토글형)** — DELETE 없음. 응답의 `isBookmarked`로 현재 상태 판별.

### 응답 (`ScrappedPlanCreateResponseDto`)

```json
{ "planId": 27, "isBookmarked": true, "bookmarkCount": 49 }
```

## 8. 인기 플랜 (내 주변 / 전국)

| 이름 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- |
| lat / lng | 내 주변만 필수 | - | 위도/경도 (double) |
| limit | 선택 | 주변 5 / 전국 3 | 페이지 크기 |
