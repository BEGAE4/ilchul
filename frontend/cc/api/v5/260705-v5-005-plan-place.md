# PLAN-PLACE API (v5)

> 원본: [api-docs.json](api-docs.json) — `plan-place-controller`

| 제목 | 메서드 | URL | 응답 스키마 |
| --- | --- | --- | --- |
| 플랜 장소 일괄 업데이트 | POST | `/api/plan-place/{planId}/update` | `UpdatePlanPlaceResponseDto` |
| 플랜 수정 프리뷰 | POST | `/api/plan-place/{planId}/preview` | `UpdatePlanPreviewResponseDto` |
| 플랜 생성 프리뷰 | POST | `/api/plan-place/preview` | `CreatePlanPreviewResponseDto` |
| 장소 스탬프 인증 | POST | `/api/plan-place/{planPlaceId}/stamp` | `StampPlanPlaceResponseDto` |

---

## 1. 플랜 장소 일괄 업데이트 — POST `/api/plan-place/{planId}/update`

코스 편집 화면에서 출발지 + 장소 목록을 한 번에 저장. v4의 PLAN-3과 동일 개념.

### 요청 본문 (`UpdatePlanPlaceRequestDto`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| departurePoint | `DeparturePointDto` | 출발지 `{ name, address, x, y }` (선택) |
| places | `UpdatePlanPlaceItemDto[]` | `{ planPlaceId(기존 매핑, 신규면 생략), placeId, order }` |

```json
{
  "departurePoint": {
    "name": "성수역 2호선",
    "address": "서울 성동구 성수동1가",
    "x": 127.0567,
    "y": 37.5447
  },
  "places": [
    { "planPlaceId": 101, "placeId": 165, "order": 1 },
    { "placeId": 200, "order": 2 }
  ]
}
```

### 응답 (`UpdatePlanPlaceResponseDto`)

```json
{ "planId": 13 }
```

## 2. 플랜 수정 프리뷰 — POST `/api/plan-place/{planId}/preview`

일괄 업데이트와 **동일한 요청 본문**(`UpdatePlanPlaceRequestDto`)으로 저장 전 결과(경로 재계산 등)를 미리 조회한다.

### 응답 (`UpdatePlanPreviewResponseDto`)

```json
{
  "planId": 13,
  "planTitle": "성수동 힙플레이스 완전 정복",
  "planDescription": "...",
  "isPlanVisible": true,
  "requiredTime": 480,
  "totalDistance": 12,
  "departurePoint": { "name": "성수역 2호선", "address": "...", "x": 127.0567, "y": 37.5447 },
  "tripStartDate": "2026-06-10T09:00:00",
  "tripEndDate": "2026-06-10T18:00:00",
  "places": [
    {
      "placeId": 165,
      "placeName": "블루보틀 성수",
      "addressName": "서울 성동구 성수동1가",
      "roadAddressName": "서울 성동구 아차산로 17길 49",
      "categoryName": "카페",
      "duration": 15,
      "order": 1,
      "stayTime": 60,
      "isStamped": false,
      "x": 127.0567,
      "y": 37.5447
    }
  ]
}
```

## 3. 플랜 생성 프리뷰 — POST `/api/plan-place/preview`

planId 없이 생성 전 프리뷰를 조회한다.

### 요청 본문 (`CreatePlanPreviewRequestDto`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| planTitle / planDescription | String | 제목/설명 |
| isPlanVisible | Boolean | 공개 여부 |
| departurePoint | `DeparturePointDto` | 출발지 |
| tripStartDate / tripEndDate | date-time | 여행 일정 |
| places | `Place[]` | `{ placeId, order }` |

### 응답 (`CreatePlanPreviewResponseDto`)

수정 프리뷰 응답에서 `planId`만 없는 동일 구조.

---

## 4. 장소 스탬프 인증 — POST `/api/plan-place/{planPlaceId}/stamp`

- `multipart/form-data` 전송

### 요청 본문 (`StampPlanPlaceRequestDto`)

| 이름 | 유형 | 설명 |
| --- | --- | --- |
| image | binary | 인증 사진 |
| location | `{ x, y }` | 인증 시점 좌표 |

### 응답 (`StampPlanPlaceResponseDto`)

```json
{
  "planPlaceId": 101,
  "isStamped": true,
  "verifiedImage": "https://example.com/stamp.jpg",
  "stampedAt": "2026-07-05T14:30:00"
}
```
