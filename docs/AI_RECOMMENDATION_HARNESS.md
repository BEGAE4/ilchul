# AI 추천과 시간 검증

프롬프트 버전은 `2026-10-02-v1`이에요. 장소 `reason`은 40자 이내 한 문장, 전체 `reasoning`은 120자 이내 1~2문장으로 친절한 해요체를 요청해요. 어미를 잘라내지 않으며, 형식·말투·시간 조건을 어긴 결과는 공유된 AI 40초 예산 안에서 한 번만 교정해요. 계속 맞지 않는 문장은 완결된 안내로 대체하고, 서버가 코스를 줄이면 이전 전체 코스 설명도 대체해요.

## 입력과 출력 경계

- 설문과 장소 문자열은 JSON 데이터로 전달해요. 템플릿 토큰을 순차 치환하지 않아요. 문자열 안의 명령을 실행하지 않도록 시스템 지침을 두고, 모델에는 도구나 저장 권한을 제공하지 않아요.
- 감정 100자, 이동 한도 문자열 30자, 후보 최대 24곳, 최종 코스 최대 5곳으로 제한해요. 후보에는 좌표와 출발·장소 간·귀환 이동 추정 행렬을 제공해요.
- Structured Outputs의 JSON 스키마와 별개로 서버가 필수 필드·정수 타입·추가 필드·후보 인덱스·중복·태그를 검증해요. 중복 JSON 키와 뒤에 붙은 JSON도 거절해요. JSON 형식은 의미나 사실성을 보증하지 않아요.
- URL·지시문·의학적 효능 등 일부 위험 표현을 검사하지만, 정규식으로 모든 공격이나 사실 오류를 판정할 수는 없어요. 실제 모델 품질은 별도 표본 평가가 필요해요.
- 웰니스 배지는 모델 출력이 아니라 서버의 출처 메타데이터로 결정해요. 공공 API와 카카오 장소는 정규화한 이름 일치와 150m 이내 좌표를 함께 확인해요. 원본에 주소가 없어 주소 일치 검증은 하지 않아요.

## 시간의 의미

`transportTime`은 코스 전체 이동 한도예요. 출발지→첫 장소 + 장소 간 이동 + 마지막 장소→출발지 시간을 모두 합산해요. `상관없어요`와 생략은 이동 한도만 없애며, 전체 일정 한도는 계속 적용해요. 예: `30분 이내`, `1시간`, `1시간 30분`.

`requiredTime`은 귀환 이동과 모든 체류 시간을 포함한 분 단위 전체 소요예요. `timeSummary`는 구간 이동, 귀환, 이동 합계, 체류 합계와 추정 여부를 제공해요. 생성 미리보기와 최종 저장에서 같은 계산기를 사용하며, 저장 요청의 `requiredTime`, `totalDistance`, `travelTime`은 계산 근거로 신뢰하지 않아요. 장소·순서·체류 시간을 바꾸면 다시 확인해요.

자가용은 카카오 자동차 경로를 구간별로 조회해요. 최대 6구간에 공유된 10초 예산을 사용하고, 조회 실패는 `PP008`로 차단해요. 같은 좌표(10m 미만)의 이동은 실제 0분으로 처리해요. 도보·대중교통은 경로/시간표 API가 없어 직선거리×1.5, 각각 4km/h·15km/h와 구간별 여유 2분·10분을 사용해요. 자동차 후보 선정에는 25km/h와 5분 여유의 추정치를 사용한 후 실제 경로로 검증해요. 이러한 추정은 강·도로 구조·배차를 반영하지 못하므로 실제 이동 시간의 상한을 보장하지 않아요.

생성 API는 `transport`, 출발 좌표, 시작·종료 일시와 장소별 `stayTime`을 요구해요. 체류는 30~90분, 일정은 양수이며 최대 24시간이에요. 새 메타데이터가 없는 기존 플랜의 순서 변경은 이전의 자가용 기준을 사용하고, 기존 체류 시간을 보존해요. 새 플랜은 이동 한도와 일정을 이후 순서 변경·일정 변경·복제 일정에도 적용해요.

## 호출과 운영

인증 계정별 Redis 임대는 추천 동시 요청 1건, 첫 요청부터 1시간 동안 최대 12건으로 제한해요. 인스턴스당 동시 처리 4건, 전체 추천 예산 90초, AI 호출 최대 2회이며 SDK 자동 재시도는 꺼져 있어요. Redis가 불가능하면 추천을 차단해요. 프론트는 요청 취소와 입력/응답 순번 확인으로 오래된 결과를 버려요.

`ilchul.recommendation.failures`, `ilchul.recommendation.quality` 메트릭에는 프롬프트 버전과 제한된 결과 라벨만 기록해요. 설문·좌표·프롬프트·응답 원문과 제공자 오류 본문을 기록하지 않아요.

`V261002120000__add_plan_trip_time_policy.sql`은 nullable 컬럼만 추가해 이전 컨테이너의 읽기·쓰기를 유지해요. 실제 DB 적용과 배포는 별도 작업이에요. 구버전 프론트는 새 생성 요청 필드가 없으므로 백엔드와 프론트 변경을 함께 배포해야 해요.

검증에는 템플릿 토큰·역할 변경 문자열·JSON 이스케이프, 잘못된 출력 타입과 인덱스, 반말/문장 잘림, 귀환 포함 시간, 미리보기 순서, 저장 값 변조, 임대 해제, 스탬프 사진 보존을 포함해요. 실제 Claude·카카오·Redis 통합 호출과 운영 DB 적용 여부는 로컬 테스트 결과와 구분해서 확인해야 해요.

스키마 요청은 [Anthropic 공식 Structured Outputs 문서](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)의 `output_config.format` 형식을 따르고, 현재 SDK 2.11.1에서는 추가 본문 속성으로 전달해요.

## 2026-10-02 로컬 검증

프론트 테스트 235개, TypeScript 검사와 프로덕션 빌드가 통과했어요. Gradle은 환경이 UDP 소켓을 허용하지 않아 시작하지 못했어요. 기존 빌드와 같은 의존성 및 Java 21로 전체 소스를 직접 컴파일하고 JUnit을 실행한 결과 297개 중 296개가 통과했어요. 변경한 추천·시간·미리보기·저장·스탬프 보존 및 새 마이그레이션 호환 검사도 포함해요.
